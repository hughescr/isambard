Date: 2026-09-04. Produced by the `izzy-phase1-blueprint` workflow (6 research readers, 3 blueprint angles judged by 3 lenses, synthesis, 3 refuters per package with fixes, completeness critic). See the *Izzy Long-Lived Session* design artifact for the decisions this implements.

Synthesis angle: strangler-with-grafts: blueprint 0 (config-flag strangler) as the spine, with judge 1's six grafts applied verbatim (P10 split into flip-then-delete with a written rollback per package; 'Requesting user' line on the one-shot path; ast-grep guard; delivered watermark behind the flag; session_opened fallback journal + reset notice; --record spike fixtures; queue-to-first-token latency), plus the flag-compatible grafts from judges 2 and 3 (compaction-guard split out of the conductor; buildSessionQueryOptions shipped on the one-shot path early; single sink-style compaction hook with a one-shot adapter; interleaved two-server askUserQuestion test; is_error resubmission via classifyClaudeError; session handle never re-invokes queryFn with reopen policy in the conductor; scheduler wraps up then reschedules rather than skipping; bare-result and per-turn cost ledger cases; FakeQuery assignable without casts). The two oversized blueprint-0 packages (P3 at 13, P4 at 21) are split so nothing exceeds 13 points.

Fifteen ordered packages. The conductor lands beside the one-shot path behind `config.session.mode: 'oneshot' | 'conductor'` (env `SESSION_MODE`, default `oneshot` until P13a), so `develop` stays deployable after every package and production never runs unflagged conductor code until it has soaked. P1-P2 are flag-independent hardening both paths need (config block, stream-extractors leaf module breaking the agent.ts<->stream-tracker.ts cycle, unified tools with cron disallowed and perTaskStopAffordance, dead status-context-builder deleted, explicit requestingUserId with an ast-grep guard and a 'Requesting user:' line on the one-shot batch, per-session MCP factory). P3-P8 build the core with no production call sites: test harness with fixtures recorded from the live spike, pure ledger reducer, session handle + input queue + query options (adopted by the one-shot path immediately) + sink-style compaction hooks + SessionStart boot-bundle hook, envelope/boot-bundle/system-prompt builders, conductor + compaction guard, journal + role-keyed resume store + retention. Every one of those is a fresh file under src/agent/session/ (or src/agent/hooks/) with queryFn, clock and journal injected, no `Stryker disable all`, measured at 100%. P9 wires the conversation conductor for Discord turns under the flag with a thin ledger-to-BotStateManager shim so presence, routing and the legacy perch/catch-up runners keep working. P10 makes catch-up the first turn, adds the delivered watermark, shutdown and crash recovery. P11 composes presence from ledgers. P12 opens the perch session. P13a flips the default with the flag kept (rollback = `SESSION_MODE=oneshot` + restart) and defines the soak; P13b deletes the flag, the one-shot agent, runners and their tests; P14 retires the mode machine and updates docs. Rollback for P1-P8 and P13b-P14 is resetting the `running` branch to the previous tag and `bun run deploy:running`; for P9-P13a it is the env var. Every package ends green on `bun test` (watch the 95% coverage floor in bunfig.toml), `bun run typecheck`, `bun run lint`, `bun run check:ast-grep`, `bun dead-code`, and `bun mutate` (dangerouslyDisableSandbox) at 100% for touched files; src/index.ts is outside the mutate glob so its wiring is pinned by tests/unit/index.test.ts and tests/integration/bot-lifecycle.test.ts instead.

### P4 · Ledger: pure, clock-free reducer over SDKMessage + conductor events, with activity-phase mapping (8 pts, deployable after)

Implement the design section 7 ledger as `reduceLedger(ledger, event) -> Ledger`: pure, structurally shared, and clock-free (every LedgerEvent carries `at: Date` stamped by the conductor; the reducer never calls Date.now()/new Date()). P4 owns the turn/envelope kind union (`EnvelopeKind = 'discord'|'perch'|'notification'|'catchup'`) and a minimal `EnvelopeMeta` so P6 imports from P4, not the reverse. Turn lifecycle from raw SDK frames typed as the SDK's `SDKMessage` (not AgentStreamEvent, whose SystemEvent lacks background_tasks_changed/task_notification): a `result` frame of ANY subtype closes the open turn (there is no 'interrupted' subtype in claude-agent-sdk 0.3.258; interruption shows up as a normal result, typically `success` with terminal_reason 'aborted_streaming'|'aborted_tools'); an assistant frame with no turn open opens a 'notification' turn. Tasks follow background_tasks_changed as the REPLACE-semantics level signal with task_started/task_notification as edges; compaction from hook events and compact_boundary; context usage from polled SDKContextUsage; per-turn cost as the delta of cumulative total_cost_usd, reset on session_opened because the counter restarts on resume; RSS from ticks; queued counts; queue-to-first-token latency per EnvelopeKind computed as firstTokenAt - turn.queuedAt; perch slot/endsAt carried on the submitted envelope. Plus a store with subscriber-throw isolation that logs via an injected logger. `phaseFromFrame` maps SDKMessage frames (not delta-based AgentStreamEvent) to ActivityPhase; stream-event-handler.ts is untouched until P11/P14.

## Synthesis risks

- Two agent paths coexist from P9 to P13b: every Discord setup file carries a conductor branch beside the old one and those files are Stryker-disabled, so branch drift is caught only by the per-branch unit tests and the dev/production soak. Keep the branches thin (delegate to the mutation-measured session modules and the two new un-disabled bridge files) and keep P13b close behind P13a.
- The ledger-to-BotStateManager shim (P9) and the legacy-perch ledger adapter (P11) are throwaway code with real tests, deleted in P12. They exist so presence, routing and the old perch gate keep working while only Discord turns migrate; if P12 slips, perch defers behind conversation exactly as today, which is acceptable but not the target behaviour.
- Fake-transport fidelity: the recorder in P3 captures frames from one Haiku spike run; ordering of task_started vs background_tasks_changed, the interrupted result subtype and the bare result must be re-recorded if the SDK is bumped. Add 're-run --record' to the SDK bump checklist.
- Per-channel independence is lost by design: one conversation session serialises turns across channels and interrupt() is session-wide. The conductor interrupts a discord turn only for the requesting channel (P7 test) and the coordinator's 'Channel Independence' suite becomes queue-behind tests (P9). Queue-to-first-token latency per source is logged from P7 and is the P13a go/no-go; the fallback is a notification-style escalation for cross-channel humans past the 30s ceiling.
- Host-driven /compact relies on getContextUsage({detail:'summary'}) fidelity and on '/compact' being accepted as a user message with the production model and two MCP sets; the spike proved it on Haiku only. P9's acceptance forces it with SESSION_COMPACT_THRESHOLD_PERCENT=5 before the flip; SDK auto-compaction stays on as the backstop, and the hook path is proven either way.
- Delivered watermark (P10) changes catch-up semantics in conductor mode: a message received but never answered before a crash reappears in the replay envelope. Intended by design 7.3, but a missed delivery-guard write would produce a duplicate answer; the journal 'delivered' entry and inboxManager.recordDelivered must both happen before the checkpoint is considered advanced, and the replay envelope text says the messages may already have been seen.
- Resume-by-id can silently fall back to a fresh session (refused resume, pruned transcript, cwd mismatch since transcripts key on process.cwd() = scratch/). The conductor journals session_opened with fallback:true and the boot bundle says 'Working memory was reset'; watch that entry during the P13a soak.
- Compaction hook consolidation in P5 touches the live one-shot path through the botStateManager adapter; it is behaviour-preserving and covered by the rewritten compaction tests, but it is the one P1-P8 package that changes production plumbing, so deploy it on its own.
- Startup ordering: the conductors must open after CLAUDE_CODE_OAUTH_TOKEN is set (index.ts:65) and after both MCP instance sets exist, and P8 moves stale-session cleanup after loadConfig so the flag can be consulted. src/index.ts is outside the mutate glob; tests/unit/index.test.ts and bot-lifecycle.test.ts pin the order.
- Coverage and mutation churn: P13b/P14 delete tens of thousands of test lines; the bunfig 95% aggregate floor can drop even with all tests passing, and the incremental Stryker baseline re-executes broadly (the runner coverage-promotion bug in memory makes incremental reuse unsafe until the runner fix ships; budget a full re-seed). Check the coverage table explicitly on each retirement PR.
- Browser MCP server attaches to the conversation session only (single WebView); perch loses browser tools in Phase 1, stated in the perch role prompt (P6).
- Two sessions share /state/* and the TaskList; each session's view refreshes only after compaction. Accepted per design; Phase 2's delta injection is the fix.
